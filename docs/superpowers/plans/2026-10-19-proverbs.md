# Proverbs Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `/proverbs` page that shows one proverb at a time, asks the learner to guess its social meaning from three choices, then reveals the meaning.

**Architecture:** A content file (`src/content/proverbs.ts`) with a validator, a page component that holds the current index and the chosen answers in React state, and review-file and validate-script wiring identical in style to tone twins. Choice order is shuffled with `seededShuffle` through the existing `ChoiceQuestion`.

**Tech Stack:** TypeScript, React, TanStack Router, Vitest + Testing Library, Playwright, `tsx` scripts.

**Spec:** `docs/superpowers/specs/2026-10-19-proverbs-design.md`

## Global Constraints

- No em dashes (U+2014) in any content or source file (`src/no-em-dash.test.ts` enforces it; in validators build the character with `String.fromCharCode(0x2014)`).
- All Yoruba strings are NFC with tone marks.
- Every proverb has `confidence: "needs-review"`, a `source`, and a `note` naming the doubt.
- No audio ships: no clips, manifest entries or play buttons.
- `wrong` has exactly two distinct strings, neither equal to `meaning`.
- A proverb with no source is left out, even if the batch ends under 20.

## Review Focus

- A wrong option that is also a fair reading of the proverb (two right answers): the reviewer must read every `wrong` pair against its proverb.
- Correct answer always in the same position: pinned by a test over all proverbs.
- Going Previous to an answered proverb must show it revealed, not re-askable.
- Empty `PROVERBS` array: the page shows a friendly message, not a crash.
- Reaching the last proverb: Next is disabled or absent, no overflow past the end.

- Produces: `export function Proverbs({ proverbs = PROVERBS }: { proverbs?: Proverb[] })`; test ids `proverb-card`, `proverb-position` (text "Proverb 1 of N"), `proverb-reveal`, buttons named "Previous" and "Next".

- [ ] **Step 1: Write failing tests** in `Proverbs.test.tsx` with a three-item fixture:

  - Next is disabled before answering;
  - choosing the correct meaning shows `proverb-reveal` containing the meaning and "You would say this when" plus `usedWhen`;
  - choosing a wrong meaning marks it wrong, still shows the correct one in the reveal;
  - after answering, Next goes to "Proverb 2 of 3"; Previous returns to proverb 1 still revealed and its choices disabled;
  - on the last proverb Next is disabled;
  - Previous is disabled on the first;
  - `proverbs={[]}` renders a friendly "No proverbs yet" message;
  - shuffle: over a 20-item fixture with ids `p1..p20`, the rendered position of the correct meaning (use `shuffledChoices("What is this proverb about?", choices, correct)`, the same prompt the page passes) is not the same index for all (at least 2 distinct positions).
